# OPC UA 节点信息窗口改进计划

## 问题分析

用户需要改进 OPC UA 节点信息窗口的显示和交互方式，主要包括以下需求：

1. GUID NodeId 按照 IPv6 地址格式显示
2. 不显示 BrowseName 和 NodeClass 信息
3. 需要显示 value 值
4. 根据 OPC UA 对象的数据类型进行不同的类型显示
5. 如果对象数据是可写属性，需要提供修改栏，让客户输入新值
6. 不同的变量数据类型输入形式不一样（例如 double 类型输入数字，字符串类型输入字符串等）
7. 点击确认修改按钮修改
8. 用户输入新值，按回车键需要设置到 OPC UA server 服务器端

## 解决方案

### 方案 1：修改 OPCUANodeTree 组件

修改 `OPCUANodeTree.tsx` 文件，调整节点信息窗口的显示内容和交互方式：

1. 修改 NodeId 显示格式，按照 IPv6 地址格式显示
2. 移除 BrowseName 和 NodeClass 信息的显示
3. 添加 value 值的显示
4. 根据数据类型显示不同的输入控件
5. 实现回车键提交功能

### 方案 2：创建新的节点信息组件

创建一个新的 `OPCUANodeInfo` 组件，专门用于显示和编辑节点信息，然后在 `OPCUANodeTree` 中使用该组件。

### 方案 3：扩展现有 Descriptions 组件

扩展 Ant Design 的 Descriptions 组件，添加编辑功能和数据类型支持。

## 实施计划

### 步骤 1：修改 OPCUANodeTree 组件

1. 修改 `OPCUANodeTree.tsx` 文件，调整节点信息窗口的显示内容
2. 添加数据类型检测和相应的输入控件
3. 实现编辑功能和提交逻辑
4. 实现回车键提交功能

### 步骤 2：修改 opcuaService 服务

1. 确保 `readNodeValue` 和 `writeNodeValue` 方法能够正确处理不同数据类型
2. 添加对数据类型的支持，确保能够正确读写不同类型的节点值

### 步骤 3：测试功能

1. 启动应用，测试节点信息窗口的显示和编辑功能
2. 测试不同数据类型的显示和编辑
3. 测试回车键提交功能
4. 测试修改后的值是否正确设置到 OPC UA server 服务器端

## 风险评估

1. **数据类型处理风险**：不同数据类型的处理可能会比较复杂，需要确保能够正确识别和处理各种数据类型
2. **用户输入验证风险**：需要对用户输入进行验证，确保输入值符合数据类型要求
3. **服务器通信风险**：修改值时需要确保与 OPC UA server 的通信正常
4. **界面布局风险**：添加编辑功能后，界面布局可能会变得复杂，需要确保美观易用

## 预期效果

- NodeId 按照 IPv6 地址格式显示
- 节点信息窗口显示 value 值，不显示 BrowseName 和 NodeClass 信息
- 根据数据类型显示不同的输入控件
- 可写属性提供修改栏，支持按回车键提交修改
- 修改后的值能够正确设置到 OPC UA server 服务器端

## 实施文件

1. `src/components/OPCUANodeTree.tsx`：修改节点信息窗口的显示和交互
2. `src/services/opcuaService.ts`：确保能够正确处理不同数据类型的读写
3. `src/types/device.ts`：可能需要扩展 OPCUANode 类型，添加数据类型和访问级别信息
